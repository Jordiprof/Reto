# ahi acaba instalado en produccion: mas superficie de ataque, mas CVEs que
# vigilar con pip-audit y mas cosas que pueden romper un despliegue que
# funciona. Estas herramientas solo hacen falta en el CI y en local, asi que
# viven en su propio fichero y en su propio lock.

# PENDIENTE: generar el lock con hashes (DEP-04, mismo criterio que el otro).
# NO se incluye ya hecho a proposito. pip-compile resuelve con el interprete
# que lo ejecuta, y este fichero se preparo bajo Python 3.11 mientras el
# proyecto y el CI van en 3.13 (pyproject.toml). Un lock resuelto en 3.11
# puede pinchar en 3.13 con --require-hashes: si 3.13 necesita un paquete que
# 3.11 no resolvio, pip se para en seco. Enviar un lock que rompe el CI seria
# peor que no enviarlo.
#
# Hay que generarlo UNA VEZ desde una maquina con Python 3.13:
#   pip install pip-tools
#   pip-compile --generate-hashes --strip-extras \
#               --output-file=requirements-dev-lock.txt requirements-dev.txt

# Mientras tanto el CI instala este fichero con las versiones exactas de
